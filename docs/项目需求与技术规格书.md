- 热门和搜索结果在已有精确 ID/URL/content_id 去重和视觉去重之后，顺序比较最近两张实际保留卡片，标题经 NFKC、大小写、空白规范化；冲突保留先出现者，不重排，不下载额外图片。相距至少三格可保留，原视觉/精确去重仍可过滤。空标题及 GIF、untitled、unknown、animation、无标题、未知等占位标签不作为真实标题。该规则可能隐藏内容不同但标题相同的邻近结果，是用户要求的展示策略，并非视觉相同判定。
- 两种数据源的热门与搜索共用规则，两种布局共用同一列表；收藏不按标题去重。分页以原始游标推进，跨页继承最后两张；仅标题碰撞导致整页为空时，一次加载最多再取两页，原精确/视觉重复整页和游标停滞仍停止。新搜索重置结果状态。
- 不改发送、转码、权限、API、阈值和原预加载参数。保留修订版安装教程；真实 Steam 滚动条渲染及搜索结果待实机验收。

## v0.1.26 — 本地 GIF 兼容性检测与体积阈值（实验）

- 依据用户关闭代理时的本地报告：正常样本 1,133,401 与 452,677 字节，待确认样本 196,663 字节，失败样本 2,671,403 字节；四者 HEAD 200、GET 200、MIME image/gif。失败样本同时具有 152 帧与 10.19 秒时长，不能证明文件大小是唯一原因。
- 不再内置任何单图例外、不读取旧 `sgpAttachmentExceptions`（旧设置保留但不再参与判断），移除记住/恢复单图菜单；保留右键仅当次作为图片文件发送。
- 原生上传开关开启时，GifSnap 官方 HTTPS CDN `/gifs/` 的 `.gif` 资源本地 HEAD 探测；若 HEAD 不可用、MIME 或长度未知则 Range GET（0–63 字节），206 以 Content-Range 总长度为准，200 用完整 Content-Length；收到响应头即取消正文读取。拒绝跨域重定向，无凭证，探测总时限 4.5 秒，HEAD 独立时限 1.8 秒。仅短暂缓存成功元数据（5 分钟，最多 128 条），合并同 URL 在途请求，不维护成功/失败名单。近可见区每次只预探测一张，点击优先；不下载全部媒体。
- MIME image/gif 且有效大小严格小于 `sgpGifLinkLimitMB` × 1,000,000 时直接链接发送，否则附件路径；未知或错误也尝试附件，下载失败则停止。设置阈值默认 2 MB，选择 0.5/1/1.5/2/2.5/3/4/6/8 MB。2 MB 为经验初值而非 Valve 官方限制。保留 GIPHY 原站候选优先、非 GIF 附件、高画质 WebP、原文件上传（8 MiB 上限）、同会话校验、单次发送；不新增权限或服务器，不自动补发。探测前捕获聊天指纹，异步完成后重新校验。
- 保留既有数据源、搜索、收藏和视觉去重逻辑。间隔重复仍是独立问题。真实 Steam 服务端预览结果及网络环境待实机验证；小于阈值不保证内嵌。仅对有权转换及重新上传的媒体启用。

## v0.1.21 — 兼容解码与累计验收

- 用户确认 v0.1.18 6/6 实机验收通过；v0.1.19 去重/横向预取尚未实机验收，不能标为通过；v0.1.20 WebP 实机报错“当前 Chromium 不支持动画解码，未发送”。
- ImageDecoder 仅暴露给 Window / DedicatedWorker，不保证扩展后台 Service Worker 可用。不能由旧报错判断 Steam Chromium 版本一定过旧。
- 优先原生 WebP ImageDecoder；不可用或初始化失败时，解析 RIFF/VP8X/ANMF，重封装静态 VP8/VP8L（含 ALPH），通过 createImageBitmap 与 OffscreenCanvas 合成，处理矩形、覆盖/混合、清除及帧时长。采用浏览器透明背景习惯，不保证完全复现特殊 ICC 色彩配置；GIF 调色板、二值透明、帧时长量化和尺寸限制继续适用。无 WASM、无远程代码、无新增权限。
- 视觉签名也可对 WebP 和 GIF 使用兼容解码。GIF89a 逐帧重封装、合成及 disposal 处理，仅用于视觉签名，不改变原 GIF 发送策略。复杂/不合法/超限/超时的素材保留，不强行去重；1 秒、最多 12 项和 4 并发预算不变。
- 附件路径仍为一次合成的 file input change 或 ClipboardEvent paste，不代表真正上传成功；不自动重发、不回退发送网址。实验开关默认关闭，仅限有权转换和重新上传的媒体。Steam 原生附件处理、真实服务后台能力仍待实测。
- 依据：https://developer.mozilla.org/en-US/docs/Web/API/ImageDecoder 、https://developer.mozilla.org/en-US/docs/Web/API/WorkerGlobalScope/createImageBitmap 、https://developers.google.com/speed/webp/docs/riff_container 、https://giflib.sourceforge.net/gifstandard/GIF89a.html 。
- 保留 v0.1.18 实机验收基线。CRX 固定签名 ID；Release 仅 CRX 和中文 HTML 安装教程；Developer 含同源码、规格、测试、打包工具，不含私钥。

## 1. 项目背景与目标

Steam 聊天中存在 `/giphy <关键词>` 的使用方式，但该命令不能可靠指定用户预先选中的某一张动图。用户希望先看见具体 GIF，再点击发送同一张 GIF，避免随机匹配。

目标是制作一个可在 Steam 桌面客户端内运行的轻量浏览器扩展：像沉浸式翻译一样拥有独立悬浮球；像微信一样默认横向浏览 GIF；像 Telegram（TG）一样具有平滑的展开、收起和切换布局动画；点击任意图片后，将其唯一链接自动填入正确的 Steam 聊天框并发送。

### 1.1 用户的现有环境

- 用户使用 Steam 桌面客户端，不是单纯在 Chrome 浏览器打开 Steam 网页版。
- 用户已经通过 Steam 内置浏览器的地址栏进入 `chrome://settings` / 扩展管理相关页面，并安装了沉浸式翻译；用户提供的截图显示其悬浮按钮出现在 Steam 好友聊天窗口中。
- Steam 的网页界面基于 Chromium 相关技术（通常由 steamwebhelper 承载）。但这一环境不必然具备桌面 Chrome 的全部 API 能力，具体版本和权限需要实测。
- 首选沿用用户已有的原生浏览器扩展加载方式。不依赖 Millennium、Extendium、DLL 注入或独立 Windows 悬浮程序。
- 建议通过 `chrome://extensions` 的开发者模式加载已解压扩展；该入口、加载行为和重启后的持久性须在实际客户端确认。

### 1.2 项目边界

**必须做到：** 独立悬浮面板、精确选择和发送 GIF、热门推荐、搜索、横向/三列布局、收藏、搜索历史、滚轮浏览、防误触和正确会话定位。

**明确不做：** 聊天命令、自定义关键词发送指令、向 Steam 原生工具栏插入按钮、重新设计 Steam 聊天界面、破解聊天协议、要求好友安装扩展、独立账号系统、默认依赖独立服务器、下载整个 GIF 收藏库。

这里的“不注入 Steam 聊天界面”指不修改其原有布局和组件；扩展仍需通过 Content Script 挂载一个独立的覆盖层，并以最小范围访问原生输入框和发送按钮。否则纯浏览器扩展通常无法做到可靠的自动发送。

## 2. 产品形态与用户流程

### 2.1 三种界面状态

1. **关闭态（悬浮球）**：默认仅在窗口边缘显示小型 GIF 按钮，类似沉浸式翻译。可拖动、边缘吸附并记住位置，不遮挡常用聊天控件。
2. **紧凑态（默认打开状态）**：顶部为搜索框、红星收藏入口和展开按钮；下方一行连续的 GIF 横向队列。鼠标滚轮向下浏览右侧，向上浏览左侧；也支持触控板横向手势。无需拖动图片。
3. **展开态**：点击展开按钮后，同一批图片平滑切换为三列纵向瀑布流；顶部搜索与收藏入口保留，结果区可向下无限滚动；点击收起按钮恢复横向队列。

横向和展开状态共享搜索关键词、已加载的 GIF 数据及收藏状态。切换布局不重新发起相同查询；尽可能保留用户正在浏览的图片附近的位置。关闭后停止后台预览播放，下一次打开默认进入紧凑态；同一会话内是否恢复上一关键词可配置，建议第一版保留直到用户清空。

### 2.2 核心用户路径

打开目标好友聊天 → 点击悬浮球 → 显示热门 GIF →（可选）输入关键词 → 停止输入 1 秒 → 展示搜索结果 → 滚轮浏览或展开三列 → 左键点击选中的图片 → 校验目标聊天 → 自动填入并发送该图片的唯一链接 → 发送成功后收起面板并恢复聊天焦点。

用户无需复制、手动粘贴或再按 Enter。失败时应保留面板并显示原因，不允许自动换一个好友或随意发送其他图片。

## 3. 功能需求（FR）

### FR-01 独立悬浮球与面板

- 使用独立的 Shadow DOM 容器隔离 CSS、DOM 事件与 Steam 原有布局；面板附着于窗口可视区域而非改变聊天排版。
- 悬浮球可拖动并吸附左右边缘；只有明确拖动悬浮球时才改变位置。区分拖动与单击，避免拖动结束误打开面板。
- 面板根据悬浮球位置和可用视口向内展开；窗口缩小时自动调整位置和尺寸，保持控件可用。
- Esc、关闭按钮、点击面板外部均可关闭面板；面板内操作不触发外部关闭。发送成功后自动关闭。
- 同一页面只存在一个扩展实例；Steam 动态重建页面或切换会话时避免重复挂载。

### FR-02 热门推荐

- 打开空搜索面板时展示 GIPHY 热门 GIF，默认请求 Trending API。
- 用户原始意图是打开即可看到流行图片，不依赖输入关键词；推荐内容随来源变化，而不是固定硬编码的 GIF。
- 第一版按服务方返回顺序展示，不在本地擅自打乱、过滤或重排 API 返回结果；若要实现随机推荐，先核对服务方现行条款及可用端点。
- 支持分页、加载状态、空状态、网络错误和重试。可采用短期缓存，避免每次开关面板都重新请求。
- 展示所需的 GIPHY 来源标识，遵守 API 现行使用政策。

### FR-03 搜索

- 顶部固定搜索框，接受中英文及其他 Unicode 文本，显示清空按钮。
- 采用 1000ms trailing-edge debounce（防抖）：最后一次有效输入后满 1 秒才发起请求，期间继续输入则重新计时。
- 中文输入法组合输入期间不触发请求；`compositionstart` / `compositionend` 处理须正确，完成选词后再计时。
- 清空关键词恢复热门；只输入空白不产生查询或历史。
- 新查询取消旧的可取消请求，或使用请求序号丢弃过期响应，避免旧结果覆盖新结果。
- 点击历史记录可立即执行搜索，无须额外等待 1 秒。
- 支持分页追加；新查询重置分页与浏览位置，布局切换不重置。

### FR-04 微信式横向滚轮队列

- 紧凑态为单行连续自由滚动的 GIF 队列，图片同高、按比例展示，不采用每次跳一格的强制分页吸附。
- 普通鼠标滚轮：向下滚动向右浏览，向上滚动向左浏览；触控板已有横向 `deltaX` 时优先保持自然横向手势，避免重复转换。
- 正确处理 `WheelEvent.deltaMode`（像素、行、页），避免不同设备速度异常；Ctrl+滚轮等缩放手势不要被错误吞掉。
- 仅在指针位于 GIF 浏览区域且确有滚动意图时处理，面板内部滚动不应联动背后的 Steam 聊天记录；移出后恢复 Steam 正常滚动。
- **禁用鼠标按住图片拖动浏览**，禁止图片原生 dragstart；悬浮球仍可拖动。
- 可通过键盘方向键浏览和选择，保证基本可访问性。
- 接近队列末尾预取下一页，追加内容不重置当前位置。分页需防重复请求、处理重复项及已到末尾状态。
- 推荐原生 CSS overflow + WheelEvent + requestAnimationFrame，借鉴成熟 Swiper / Embla 的鼠标滚轮与点击保护机制，不强制引入轮播库。

### FR-05 三列纵向瀑布流

- 点击展开按钮切换为三列，图片保持合理宽高比、紧凑间距；展开模式正常纵向滚轮浏览。
- 不重新下载已经加载过的预览，不重新搜索。保持同一搜索/收藏数据和可见项附近的浏览位置。
- 尽量保持服务方结果顺序与键盘可访问顺序；可使用按顺序的网格/受控瀑布流布局，避免多列 CSS 导致顺序混乱。
- 对极窄窗口可自适应减列或调整尺寸以防溢出；三列是正常窗口宽度下的目标。

### FR-06 一键精准发送（核心）

- 左键有效点击 GIF 卡片，发送该卡片绑定的唯一 GIF 链接，而不是调用 `/giphy` 或重新搜索关键词。
- 将会话定位在用户打开面板时对应的聊天窗口，点击前重新验证会话与输入框仍对应；如果已切换、关闭或无法唯一识别，必须中止发送并提示重新选择聊天。
- 发送内容必须与选中图片的 ID 一致。优先使用经实测能被 Steam 内嵌显示的规范 GIPHY 链接；区分预览 URL、详情页 URL 和实际发送 URL。
- 通过原生输入框的受支持输入方式填入链接，触发原有发送操作。无需直接调用未公开聊天协议；优先避免修改全局系统剪贴板。
- Steam 若使用 React 等受控输入框，需实测输入事件和发送按钮行为，不能假设设置 `value` 或模拟键盘事件就一定成功。
- 保留用户未发送的草稿：若能够可靠地暂存、单独发送 GIF 并恢复草稿，可采用此方案；若无法可靠保证，则提示用户先处理草稿，不得将草稿和 GIF 一并误发或覆盖草稿。
- 如果会话状态变化、输入框不可用、发送按钮禁用或离线，停止并反馈。禁止无确认的自动重试，避免重复发送。
- 必须串行化发送，防止快速点击重复发送；确认成功才收起。无法确认是否已发送时提示“发送状态未知，请查看聊天”，不伪报成功。
- 同一链接是否会被 Steam 对发送方和接收方渲染为 GIF，需要使用两端真实账号或测试好友验证；接收方关闭媒体预览时可能只显示链接。
- 若客户端限制导致无法实现可靠的一键发送，可临时提供明确标识的“复制链接”回退模式，但不能把它当作核心需求已完成。

### FR-07 红星收藏

- 每张 GIF 卡片右上角显示五角星：未收藏为灰色空心，已收藏为红色实心（建议 #EF4444）。星标点击与发送事件完全隔离。
- 点击顶部红星进入“我的收藏”；再次切回热门/搜索结果。收藏也支持横向与三列布局。
- 仅保存唯一 GIF ID/网址及必要的预览元数据，不下载或永久存储 GIF 二进制文件。
- 按规范 ID 去重，同一个 GIF 不重复收藏；再次点击星标取消收藏。建议默认按最近收藏顺序显示。
- 收藏立即本地持久化，重启 Steam 后仍存在；多个聊天窗口中的收藏变化同步。
- 预览链接失效时显示占位并提供复制原链接或删除选项，不能因一张失效图导致整个收藏夹不可用。

### FR-08 图片右键菜单

- 对扩展自身的 GIF 卡片拦截 `contextmenu`，呈现自定义菜单；不改变 Steam 其他区域的右键行为。
- 菜单至少支持：添加到收藏 / 取消收藏；建议同时提供复制 GIF 链接、打开原始页面、发送 GIF。
- 右键本身绝不发送 GIF。选择菜单中明确的“发送 GIF”才走正常发送流程。
- 支持 Esc 或点击外部关闭菜单；菜单根据视口调整位置，避免出界。

### FR-09 历史搜索记录

- 搜索框为空并获得焦点时，或点击历史入口，显示最近搜索记录。
- 只有完成 1 秒防抖、实际发起的非空查询才记录；输入中间状态不记录。网络请求是否成功不影响已发起查询的历史记录。
- 相同关键词去重并移到最前；建议 trim 后按不区分英文大小写比较，显示保留原始输入。
- 建议默认上限 50 条；支持点击历史词立即搜索、删除单条、清空全部。
- 历史保存在扩展本地存储，重启 Steam 后恢复；不发送到独立服务器或用于遥测。

### FR-10 防误触

- 滚轮浏览期间不允许触发图片发送，最后一次相关滚动停止约 150ms 后再恢复；若平滑滚动仍在继续，延长保护至实际停止。
- 左键按下到松开之间的最大位移超过约 6 CSS px 时不判定为有效发送点击；滚动或布局切换期间开始的点击不得在结束后意外补发。
- 禁用图片原生拖拽；星标、右键菜单、搜索框、布局按钮均须独立事件处理，不冒泡为 GIF 发送。
- 只允许真实用户的明确点击或键盘激活操作触发发送，自动滚动、加载、悬停、搜索完成都不触发发送。
- 发送过程中只允许一个事务，失败或状态未知时不自动重发。

## 4. 视觉设计与动画

整体风格：适配 Steam 深色主题，参考 Telegram 的弹性过渡与微信的快捷横向浏览。不要照搬第三方产品的品牌标志或整个界面。

| 项目 | 建议默认值 |
|---|---|
| 悬浮球 | 42 × 42 CSS px |
| 紧凑面板宽度 | 380–480 px，根据视口调整 |
| 横向预览高度 | 100 px |
| 展开面板结果区/面板高度 | 约 420–520 px，受视口限制 |
| 展开列数 | 3 |
| 面板圆角 | 16 px |
| 图片间距 | 4 px |
| 背景 | 深色半透明，适度毛玻璃（建议 blur 20px，可降级） |
| 展开/布局过渡 | 约 220–280ms |
| 收起 | 约 180–200ms |
| 图片淡入 | 约 150ms |
| 收藏标志 | 灰色空心 / 红色实心 |

- 悬浮球展开、面板缩放、透明度过渡要自然，使用 transform / opacity，建议用 FLIP 等方式实现两种布局的连续过渡。
- 图片加载用骨架屏和轻微淡入，不闪白；悬停效果适度，不应造成布局移动或误触。
- 滚轮采用连续自由滚动，不强制吸附。不为每次 wheel 事件堆叠独立 smooth-scroll 动画；可使用单一 RAF 插值循环，原生触控板手势尽量保持自然。
- 遵循 `prefers-reduced-motion`，减少动画时仍保留全部功能。
- 所有尺寸与时间除明确的 1000ms 搜索防抖外均为初始建议值，可实测调整，不是外部组件的官方默认值。

## 5. 技术架构

### 5.1 技术选型

| 项目 | 首选 |
|---|---|
| 运行环境 | Steam 桌面客户端内置 Chromium |

| 开发语言 | 原生 JavaScript，HTML/CSS |

普通 Chrome / Edge 与 Steam 网页版可作为调试环境和可选兼容目标，但不能替代 Steam 桌面客户端验收。

### 5.3 请求与权限

- 先使用开发者工具确认 Steam 实际聊天页面 URL、文档/iframe 结构、执行上下文及 CEF 版本，再设置最小范围的 content script matches / host permissions。不要凭空写死未经验证的 Steam DOM 选择器。
- 仅申请必要的存储和 GIPHY API 主机权限；只有确有需要时才申请剪贴板或额外主机权限。不得请求全网站访问、读取 Cookie 或读取 Steam 登录凭证作为默认方案。
- GIPHY 搜索和热门 API 通常需要 API Key。开发阶段由用户/开发者配置其自己的 Key，不能编造 Key 或把真实密钥提交到公开仓库。
- 客户端扩展中的 Key 不能视作服务器级秘密。发布版本需按 GIPHY 的现行密钥、配额、展示、内容分级及授权条款设计；如果政策或配额要求后端，则应单独说明并征求是否改变当前无服务器约束。
- 可参考端点 `https://api.giphy.com/v1/gifs/trending` 与 `https://api.giphy.com/v1/gifs/search`，使用配置的 `api_key`、`limit`、`offset`、搜索 `q` 等参数；最终参数以官方文档为准。
- 检查超时、HTTP 401/403、429、网络错误、空数据、分页结束；清楚提示错误，不循环重试或持续刷接口。
- 预览资源使用适合列表的较小体积动态图版本，发送使用已确认兼容的唯一链接，不发送低质量缩略图替代原图。
- 默认每页 25 张为建议值，以服务方限制和实测性能为准。

### 5.4 数据结构（示例，不代表实际 GIF）

```json
{
  "schemaVersion": 1,
  "favorites": [
    {
      "id": "example-gif-id",
      "url": "https://giphy.com/gifs/example-gif-id",
      "previewUrl": "https://media.giphy.com/media/example-gif-id/giphy.gif",
      "width": 320,
      "height": 240,
      "addedAt": 1795700000000
    }
  ],
  "searchHistory": [
    { "query": "cat", "searchedAt": 1795700000000 }
  ],
  "settings": {
    "floatingPosition": { "edge": "right", "yRatio": 0.65 },
    "historyLimit": 50,
    "searchDebounceMs": 1000
  }
}
```

运行时 GIF 模型建议包含 `id`、`pageUrl`、`previewUrl`、`sendUrl`、尺寸及可选描述。收藏持久化时只保留必要字段；发送 URL 若与详情页不同，须保存或可确定性重建。不得根据关键词重新选取图片作为收藏/发送。

### 5.5 状态机与关键事件

```text
UI: closed <-> compact <-> expanded
Data source: trending | search(query) | favorites
Request: idle | loading | ready | empty | error | exhausted
Send: idle -> validating -> submitting -> confirmed | failed | unknown
```

- 布局状态与数据来源状态分离；切换 UI 不改变查询、分页或收藏数据。
- 搜索、分页与收藏更新须有独立的状态管理，避免重复渲染和过期数据覆盖。
- `ChatAdapter` 建议暴露 `getActiveConversation()`、`resolveTarget()`、`validateTarget()`、`sendGifUrl()` 等抽象方法；这只是项目内部接口建议，不是 Steam 官方 API。
- `MutationObserver` 用于监听页面/聊天 DOM 动态重建时应限定范围并节流，避免持续全页扫描。
- 多会话窗口的面板和发送目标独立，共享收藏、历史和设置。数据写入需考虑并发，防止两个窗口同时收藏造成覆盖。

## 6. 性能、隐私及安全要求

- 仅加载/播放可见区域的动图及少量邻近预取；隐藏面板时释放不必要的媒体资源并暂停播放。普通 `<img>` GIF 不支持原生 pause，必要时切换静态缩略图、移除动态 src 或采用支持暂停的视频预览（以 API 许可为准）。
- 使用 IntersectionObserver 管理预览；长列表考虑 DOM 回收或虚拟化，避免无限累积图片节点。
- 延迟挂载大面板，控制并发请求、缓存容量和图片尺寸。扩展不能明显影响 Steam 滚动或游戏运行体验。
- 收藏、搜索历史、悬浮球位置保存在本地；除用户输入的搜索词发给 GIPHY 及预览资源请求外，不向外部服务上传聊天内容、好友名单、Steam 账号信息或草稿。
- 不记录敏感聊天内容到日志。不读取登录凭证、不使用 Cookie 模拟 Steam 请求、不绕过用户认证或平台限制。
- API 返回文本通过安全的 DOM 方法渲染，不把不可信内容插入 innerHTML；仅允许预期的 HTTPS 来源和经校验的 URL。
- 不远程加载并执行 JavaScript；不关闭 Chromium 沙箱、安全策略或 Steam 安全功能来完成安装。
- 遵守 Steam 和 GIF 数据服务适用的规则。自动发送仅在用户明确点击时执行，不提供批量群发、定时发送或后台自动发送。

## 8. 开发顺序与里程碑

### M0 — 可行性验证（必须优先）

1. 在用户现有 Steam 环境加载最小扩展，确认 Manifest V3、Content Script、Shadow DOM、Storage 和必要网络权限是否正常。
2. 识别好友聊天的实际 URL、多个聊天窗口/会话的结构以及原生输入控件。
3. 在测试聊天中手动粘贴一个已知 GIPHY 唯一链接，验证双方渲染情况，确定正确的发送 URL 格式。
4. 用最小测试按钮，在用户明确点击时填入同一链接并触发原生发送，验证草稿保护、会话定位与发送状态判断。记录实际选择器与兼容限制。

若 M0 不通过，先诊断原生扩展环境；不得虚构成功。可提供可安装 UI 原型及复制链接回退，但须将自动发送或客户端加载问题列为未完成阻塞项。

### M1 — 界面与浏览

完成悬浮球、横向滚轮浏览、三列展开、动画、响应式、键盘操作和防误触逻辑。可使用明确标为 mock 的本地测试数据验证界面；正式模式不得将 mock 结果当成真实热门数据。

### M2 — GIPHY 接入

配置 API Key，完成热门、搜索防抖、输入法兼容、请求取消、分页、错误提示和预览懒加载。

### M3 — 收藏与历史

实现红星、右键菜单、收藏夹、历史下拉、去重、删除及跨窗口持久化同步。

### M4 — 正式发送集成与验收

将 M0 验证过的 ChatAdapter 集成，完成会话校验、草稿保护、状态反馈、防重复发送与性能优化；在 Steam 桌面客户端执行以下测试。

## 9. 验收标准（Acceptance Criteria）

| ID | 场景 | 通过条件 |
|---|---|---|
| A01 | 扩展安装 | 在 Steam 桌面客户端实际加载，悬浮球出现；不只是 Chrome 网页版成功 |
| A02 | 聊天布局 | 不修改原生工具栏、聊天框布局或好友列表；关闭面板后不占用布局空间 |
| A03 | 悬浮球 | 单击展开，拖动后吸附；拖动不误触展开，重启后位置恢复 |
| A04 | 热门 | 空查询打开时显示真实热门 GIF，网络错误有提示 |
| A05 | 防抖 | 例如连续输入 c、ca、cat，间隔均小于 1 秒，只在最后输入满 1 秒后请求 cat |
| A06 | 输入法 | 拼音组合输入过程不产生无意义查询；最终选词后正确触发 |
| A07 | 请求竞态 | 慢返回的旧查询不能覆盖新查询；清空后恢复热门 |
| A08 | 横向滚轮 | 鼠标上下滚轮分别浏览左/右方向，触控板横向自然工作；不拖动聊天记录 |
| A09 | 禁止图片拖动 | 按住图片移动不执行发送，也不出现原生图片拖拽 |
| A10 | 滚动保护 | 滚动期间及保护期内误点不发送；停止后正常左键点击可发送 |
| A11 | 展开切换 | 三列纵向浏览正常；切换两种布局不丢查询或收藏、不重复请求同一页 |
| A12 | 分页 | 接近末尾继续加载；不会重复分页、无限请求或突然跳回起点 |
| A13 | 精准发送 | 连续选择不同 GIF，各自发送其绑定唯一链接，而不是随机图片 |
| A14 | 接收端 | 在允许内嵌媒体的测试会话中确认接收方看到预期 GIF；如只能显示链接则记录兼容限制 |
| A15 | 多会话隔离 | 打开 A 好友面板后切换 B 时，不得误发给 B；会话失效则阻止发送 |
| A16 | 草稿保护 | 输入未发送文字后选 GIF，不能覆盖或连带发送原文字；不支持安全恢复时提示 |
| A17 | 失败/重复保护 | 发送失败不关闭面板、不声称成功；连续点击不重复发；状态未知不自动重试 |
| A18 | 红星 | 点击空心星变红、再次点击取消；星标操作不会发送 GIF |
| A19 | 右键 | 打开收藏菜单，右键本身不发送；收藏/取消收藏与星标同步 |
| A20 | 收藏持久化 | 重启 Steam 后收藏仍可见、可发送；重复收藏不产生两份数据 |
| A21 | 历史 | 实际查询写入记录；重复词置顶；单条删除、全部清空、点击立即搜索均正常 |
| A22 | 历史持久化 | 重启 Steam 后恢复未清空的历史，多个窗口同步 |
| A23 | 性能 | 收起面板后无持续的大量预览下载/播放；长列表不卡死，无明显聊天滚动卡顿 |
| A24 | 权限与隐私 | 无多余权限、无凭证采集、无聊天数据上传、无非用户触发的发送 |
| A25 | 兼容降级 | API Key 缺失/限流/失效、客户端 API 不支持、窗口过窄等场景有可理解的反馈 |

性能目前无约定的硬件环境、帧率或内存硬指标，开发时应记录测试环境和实际表现，不虚构基准成绩。

基于 v0.1.19；在 GifSnap 设置开启“WebP 转 GIF / PNG 并上传（实验）”，保存后点击你有权转换和重新上传的 WebP。默认关闭，原有 GIF 链接发送、原站兼容、搜索、收藏、去重与预取保留。GifSnap 文档 https://gifsnap.com/docs 说明接口媒体权利独立于 SDK 许可；不能假定所有结果均获准重新上传。仅处理用户选择的、来自 `https://media.gifsnap.com/` 的 WebP；后台无凭据请求、拒绝跳转，内存处理，不落盘，不使用中转或额外权限。

解码采用 ImageDecoder；OffscreenCanvas 逐帧绘制，自带 GIF89a/LZW 编码器（252 色加二值透明、保留帧序和近似时长、循环次数），静态输出 PNG。输入、输出各限 8 MiB，最多 180 帧、30 秒，原图最多 1600 万像素，最长边 400 px，GIF 超限尝试 240 px。超限、超时或不支持解码时停止，不发送链接。极短帧最低 20 ms，颜色和分辨率可能下降。

后台准备完成后二次核对当前 composer 与会话标识，只向唯一明确关联的表单图片 input 提交一次 change，否则向当前 composer 提交一次含 File 的 paste；不改系统剪贴板、不触发 Enter、不点击 Steam 确认、不自动回退或重发。附件交接不等于服务器上传成功。若 Steam 弹出确认窗口，由用户确认；若无反应请检查聊天，不要立即反复点击。

验收：启用后使用合法测试动图验证 WebP→GIF 播放、静态→PNG、附件确认与单次提交；切换聊天期间取消；失败不发链接；保留草稿。测试环境页面导航受管理策略限制，使用 Pillow 解码真实 WebP 测试帧、模拟 ImageDecoder、真实 Chromium Canvas 和 Pillow 独立检查 GIF/PNG，不能代替 Steam WebCodecs 实机测试。
